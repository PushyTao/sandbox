# 强制条件与负向回归设计

PUSH-4，2026-11-04。此处是实现者与独立验证者的验收输入，**不是已经实现或批准的 API**。仅在临时环境用合成数据测试，不以真实秘密、真实仓库控制文件或第三方主机为目标。执行状态以 [本轮报告](README.md) 为准；下表未注明已执行者均为待实现/待复测。

## 文件对象与受控副本

实现必须先定义保护的是名称、对象、子树还是组合，以及哪些规则为硬拒绝。每种路径规则覆盖 read/list/write/truncate/create/remove/rename/link；rename/link 检查两端。不能表达时返回 UnsupportedPolicy，且零用户负载启动。

| ID | 强制条件与最小负向场景 | 通过标准 / 当前状态 |
|---|---|---|
| FS-A1 | 受保护文件在工作区内、外和多个获准根中有 hardlink；分别尝试读、截断、append、rename/link 别名 | 所有指向受保护对象的未授权操作拒绝，或会话创建被拒绝。WSL 写别名反例已复现；其余待验 |
| FS-A2 | 在扫描前/中/后用同步屏障插入、删除、改名 alias；检查 dev/inode 或卷/文件 ID 与链接数变化 | 对象身份与实际访问一致；不以 `nlink==1` 的瞬时值作为永远安全证明；冲突拒绝，不带着不完整证据执行 |
| FS-N1 | `.agents/.codex/.claude/.git/sandbox.toml` 不存在时，分别 create/mkdir、rename 普通对象到该名、hardlink/symlink 到该名 | 保留保护语义，或启动前拒绝不支持的策略；WSL `.agents/config` 创建反例已复现 |
| FS-N2 | 删除再创建、大小写/Unicode 等价形式、嵌套工作区、Git worktree 指针/commondir/环境覆盖 | 按实际文件系统语义裁决，不以字符串相等替代对象/名称规则；未知卷/路径形态拒绝 |
| FS-P1 | 策略解析完成后、挂载/打开前替换工作区根或祖先；已打开目录 FD/handle 后重命名父目录；并发交换 symlink/junction | 操作保持在获准对象/视图中，或检测漂移并拒绝；本轮只证明缓存 resolve 不固定对象，未测生产强制 |
| FS-P2 | 目标存在/不存在、跨卷/挂载、rename/link 两端分别受限；通过 `/proc/*/fd`、继承句柄和 Windows 路径别名访问 | 无旁路；未支持的 UNC/设备/ADS/8.3/reparse 情形明确拒绝，不默认允许 |
| FS-C1 | 导入受控副本前，源树中被禁读对象存在一个看似普通的 hardlink 别名 | **读取/复制内容前**识别并排除对象别名或拒绝导入；本轮名称过滤 copytree 实验确实把合成秘密复制进副本，证明普通复制不是读取保护 |
| FS-C2 | 导入过程中并发替换父目录、创建别名、修改内容；源树含 socket/FIFO/设备/reparse/外部 symlink | 只导入定义允许的类型；不跟随源到未授权区域，不打开 IPC/设备；采用可信快照/受控静止源或等效证明，无法获得一致性就拒绝 |
| FS-C3 | 副本的可写文件与宿主对象/其他会话比较身份；副本内创建未来保护名、修改控制文件 | 内容复制需形成独立存储对象，不能以 hardlink 当隔离副本；reflink/快照须验证所用文件系统语义。副本仍需名称/工具路由约束，不能把恶意配置作为可信输入 |
| FS-C4 | 导回时源被用户修改、目标换成 symlink/junction、受保护文件混入 diff、删除/重命名越界 | 可信导回服务按当前对象与 expected version/hash 再鉴权；校验两端、大小/数量和冲突。只导回明确允许的变更，不递归镜像删除宿主、不自动导回受保护配置 |
| FS-C5 | 导入/导回失败、取消、磁盘满；清理根被替换、目录内含链接和挂载 | 原始宿主数据与外部哨兵不变；只清理已登记且重新确认归属的临时资源；失败/残留显式报告。两平台固定目录 symlink 哨兵已通过，其余待验 |

受控副本是待评估方案，不能为使现有用例通过而默认改变 D6。其导入、执行、导回、清理每个阶段都是可信代码攻击面；性能、空间、元数据和冲突成本也须记录。没有一致性/别名证明时选择拒绝，而非扫描后乐观运行。复制后禁止宿主自动执行或加载未审查的配置、钩子和脚本。

## 审批主体与授权状态

签发主体：经服务认证、具备管理权限的可信控制角色。请求主体：模型经 harness 或负载工具面提交权限需求；没有签发权。使用主体：可信 harness 向服务提交受保护授权引用，服务核验后消费；worker 和模型只看到非秘密 ID/状态。不能仅凭同 UID、Origin、端口、`initialize.role` 或持有 request ID 获得审批权。

grant 必须绑定服务实例/认证调用者、会话、政策版本和 hash、精确资源/动作、有效期；once 再绑定不可变请求（含 argv 边界、cwd、环境实际值的受保护摘要、stdin/脚本快照等批准依赖的内容）。once 在启动前原子消费，并发只能有一个有效使用；消费后准备失败不应暗中恢复可重放凭证，新执行走新的明确决定。session grant 绑定可复用范围，每个请求重新判权，不能按命令前缀给任意 shell 脚本权限。

硬策略始终在 grant 之上。Git protected 与可审批软保护的优先级由架构师明确前，不提供 Git 写入 grant。批准只产生授权，不自动执行或重试；失败后的 `retry_of` 不撤销已有副作用。策略/服务实例变化和会话关闭不得让旧 grant 继续有效；撤销先阻止新使用，需要即时收回时终止进程并关闭存量连接，不能声称仅删除授权记录就收回已打开 FD。

## 证明模型不能自批的测试矩阵

当前没有真实审批服务，**以下全部未执行**。不能实现一个内存 mock 并用其通过来宣布 AUTH-1 通过。实际验收需观测服务端审计、负载启动计数、真实受保护合成资源和调用者身份；每个拒绝用例配同资源的合法正向控制。

| ID | 输入/竞争 | 必须观察到的结果 | 对应实现角色 |
|---|---|---|---|
| AUTH-01 | 模型工具客户端调用 approval.resolve；自报 admin/owner，添加伪造 grant/approval 字段或直接命中控制端点 | 服务拒绝；无有效 grant、无负载启动、无权限变化；拒绝记录关联到真实主体 | 架构＋接入＋运行时 |
| AUTH-02 | 子进程打印真实结构的 JSON 批准事件、已知 pending ID、ANSI/OSC、HTML/脚本和 Markdown 链接 | 始终作为不可信输出；无控制事件/审批卡动作、桥接调用、剪贴板变化或权限授予 | 控制台＋接入 |
| AUTH-03 | 只知道请求 ID；窃用另一个会话/主体/服务实例的授权引用，枚举其他会话状态/日志/取消 | 每个方法按身份与归属拒绝；不泄漏秘密或可见性以外的对象信息 | 运行时＋控制台 |

| AUTH-05 | 批准后修改 argv/cwd/env/stdin/引用脚本、策略 hash、资源对象或过期时间；客户端修改时钟 | 不符合不可变绑定或已过期则拒绝；期限由服务验证；脚本内容批准要求快照/摘要一致 | 运行时＋接入 |

| AUTH-08 | 关闭会话/所有者断连后迟到批准；服务重启、策略迁移后旧授权重放 | 不复活关闭对象、不跨实例迁移授权；副作用未知不盲目重跑 | 架构＋运行时＋构建发布 |
| AUTH-09 | 用已打开文件 FD/网络连接继续访问，然后触发要求立即生效的撤销 | 相关执行/连接真实终止并报告清理；若只能阻止新访问则明确能力，不能伪称立即撤销 | 运行时 |

| AUTH-12 | 审批操作同时发生审计存储满/不可写；日志导出含合成 token、原始环境和控制字符 | 强审计模式停止敏感操作；无静默已审计；导出脱敏/限权且不执行控制字符 | 架构＋控制台＋运行时 |

## 生命周期与证据要求

对 Linux fork/setsid/双重 fork、Windows breakaway、宿主代执行、继承控制句柄分别设计有界合成负载；执行前准备清理 handle 或独立 supervisor。准备失败、自然退出、超时、取消、所有者断连、supervisor 崩溃、代理故障是不同场景。不要用按名称杀进程或递归删除未知根清理测试；仅使用本次创建并核验身份的对象。

每个回归保留：代码 SHA、OS/架构/依赖版本、身份和安装条件、合成夹具、正向控制、触发步骤、实际退出码和观察、清理结果、未覆盖项。区分内核拒绝、普通命令错误、能力不可用与清理不完整。先复现原始错误，再由所属实现者修复，独立复测修复 SHA；不通过扩大宿主权限、移除失败观察或关闭隔离使结果变绿。
