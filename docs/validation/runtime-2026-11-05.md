## 实验设计与清理边界

采用现有 Job-close 实验扩展，而非引入新 supervisor 子系统：它能直接隔离“只杀根进程”与“观察到的后代确实退出”的差异，且不需要修改宿主安全设置。supervisor 强杀实验仍应另行加入外部观察者和异常启动清理设计。

1. 创建非继承、无 breakaway 标志的 Job，设置 KILL_ON_JOB_CLOSE；挂起创建固定 Python 子进程并归组后再恢复。
2. 固定子进程仅创建一个固定 Python 孙进程，均带 `-I -S`；孙进程原子发布 PID 标记并 sleep 20 秒。父进程等待最多 20 秒，必要时 kill 并最多再等 5 秒。无用户负载参数、网络操作或继承 Job handle。
3. 最多等 5 秒准备；读取本次临时目录的标记，用 OpenProcess 保留确切句柄，IsProcessInJob 指定本实验 Job，验证两进程仍在运行。
4. 关闭 Job；分别最多等 5 秒确认根与孙进程句柄 signaled，并采集孙进程退出码。退出码为 0 本身不证明成功，成功还需关闭前存活及归属成立。
5. finally 关闭仍持有的 Job，对根进程回退终止并等待。只对已验证归属的孙进程句柄回退终止；查询失败时通过 Job 清理并等待保留句柄。未确认退出或句柄/目录清理错误必须 fail；回退清理不能将原失败观察改成 pass。
6. 测试只模拟 IsProcessInJob 失败，其余 Job/创建/关闭/等待使用本机 API；测试在失败点 DuplicateHandle 留下独立观察句柄，避免事后查 PID 时将 PID 复用或访问失败误当成退出。

准备和等待有界不等于所有 Win32 调用都有硬实时上界。采集器再使用已有安全团队的外层 Job，单命令 60 秒期限；该保护是研究测试装置，不能据此声称产品恢复能力。其记录均为 `cleanup.complete=true`、`active_after_cleanup=0`；被测探针返回前的孙进程退出由内层测试验证，不能靠外层事后清理补成通过。

仍未覆盖：多级/并发大量后代、supervisor 强杀、breakaway/WMI/宿主代理、全部 CloseHandle/TerminateProcess 失败组合、资源压力、恶意标记篡改。标记来自可信固定程序，不是生产控制通道设计。

## 文件策略：受控副本与拒绝路径比较（提案）

| 路线 | 可解决什么 | 仍须满足的条件 / 代价 |
|---|---|---|
| 直接工作区，无法证明则拒绝 | 避免把路径挂载误称为完整对象保护；不产生同步覆盖 | 在负载开始前判定所请求的硬保护不可表达并返回不支持。一次扫描、realpath、预建占位目录都不足以证明并发 hardlink/rename/父目录替换安全。当前 PoC 只报告反例，没有实现生产拒绝编译器 |
| 会话受控副本 | 新对象存储可隔离对原始 inode 的写入，便于评审产物 | 复制入口仍可能通过允许名称的 hardlink 读出保护内容；仅按名字排除 `.git` 不够。需可信输入快照/对象与读取授权、禁止跨会话链接或 reflink 语义误承诺、私有 HOME/temp、输出配额 |
| 副本结果合并 | 使工作区变更可审阅、可逐项授权 | 禁止自动回写 protected/未来控制名；校验基线版本与内容摘要，固定目标对象与父目录身份，检测冲突/别名/并发替换，限制链接和特殊文件。拒绝不可安全合并项，不以重试覆盖用户改动 |

推荐的下一步实验是只用合成数据验证受控副本的读别名与受保护路径回写拒绝，并与直接路径的启动前拒绝比较；这不是 D6 的已批准产品选择。无论选哪条路线，都不能删除当前两个失败观察来提高报告评级。
