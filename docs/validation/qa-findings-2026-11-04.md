# PUSH-5：反例、证据缺口与回归条件

基线 `c19b23585d64d20869adb9654cfbc1f013584d40`。本轮未修改 `tools/m0`。QA-01/02 是先前已知、本轮独立重现的候选方案安全反例，不是新增已修复产品缺陷；QA-03 是本轮观察到的环境归档缺口。最小复现仅使用一次性合成目录和固定代码，严禁替换为真实秘密或仓库元数据。

## QA-01：只读子树可由可写 hardlink 别名改写

影响：阻塞任何声称完整 FS-4/protected 语义的产品发布；不阻塞清楚标注限制的研究代码保存。

环境：WSL2 Ubuntu 26.04 LTS / x86_64，内核 `6.6.114.1-microsoft-standard-WSL2`，Python 3.14.4，bwrap 0.11.1；合成目录位于 v9fs。观察频次为 2/2 次：一次 opt-in 集成套件调用，一次独立 CLI 调用；不是压力测试或其它平台复现率。

最小复现：从 `tools/m0` 运行 `python3 -m sandbox_probe --output <任务目录>/probe.json`，读取 `FS-4.hardlink`。具体构造在 `linux.py:143–173`：合成 `protected/control` 初值 `synthetic control`，将 `protected` ro-bind，将同一文件硬链接到可写工作区 `alias`，由沙箱固定进程写 alias，再在保护路径和宿主两侧读回。

期望：若声称受保护文件不可变更，别名写必须拒绝，或无法表达策略时在负载开始前明确拒绝。实际：两侧均读到 `alias bypass`，`bypass_reproduced=true`，观察为 fail，CLI exit 1。原始证据 `qa-evidence-2026-11-04/wsl-ubuntu/probe.json` 与 `unit-integration.stderr.txt`。

初步归因：该挂载方案只约束一个路径视图，可写别名仍引用相同文件内容；不是 Python 测试断言错误。回归条件：运行时提供新的 SHA 和策略支持声明，验证已有/并发 hardlink、rename、打开 FD 与父目录替换；对支持场景证明内容不变，对不可表达场景证明零负载启动并有结构化拒绝。不能把旧探针 fail 改成 pass 而不实现或拒绝该策略。

## QA-02：已有保护挂载不预留未来 Agent 配置名

影响、环境和本轮频次：同 QA-01，2/2 次复现；禁止把工作区可写解释为可以安全保护所有控制文件名。

最小复现：同一 CLI，查看 `FS-4.future-name`；构造在 `linux.py:174–178`，初始不存在 `.agents`，在可写工作区创建 `.agents/config` 写入 `future bypass`。

期望：规则保护未来名称时，创建应被拒绝，或在会话启动前拒绝不能表达的组合。实际：创建成功，`bypass_reproduced=true`，报告 fail；正常现存目录 ro-bind 保护通过不覆盖未来名称。

初步归因：固定计划只有已有目录的挂载，没有名称预留或政策编译/拒绝机制。回归条件：覆盖 `.git`/`.agents`/其它受支持控制名称的不存在→创建、父目录替换、大小写/别名、并发创建；选择受控副本时验证同步/合并不会重新引入旁路。安全与运行时按新 SHA 共同复核，不修改旧证据。

## QA-03：同一 Windows 宿主的环境版本随解释器而变

等级：证据质量问题；影响平台覆盖归档和版本适用性，未观察到它造成 Job 测试误判。

最小复现：在同一宿主分别用 Python 3.8.5 与 3.12.3 执行完整报告 CLI，比较 `platform.release/version`。本轮两个解释器各 1 次，两个报告时间间隔约 14 秒；没有更换 OS。3.8.5 返回 `10 / 10.0.26100`，3.12.3 返回 `11 / 10.0.26300`；独立只读注册表查询为 build `26300`、UBR `9711`。三个原始值分别见 Windows 两份 probe.json 和 `windows-host.json`。

期望：发布证据能区分真实宿主 build、Python 所报告版本和采集来源。实际：当前 `report.py:52–60` 只记录 `platform.*`，单独阅读旧解释器的 JSON 可能把本机归到另一 build；报告仍有 Python 版本，但不足以自动解释差异。

初步归因范围：报告直接使用解释器 `platform` 元数据，解释器/OS API 行为差异的更深原因本轮未证明，不据此断言具体系统兼容机制。建议保留原字段，另记录可信宿主 build 与来源；本报告已补充注册表证据，没有改写原始报告。

回归条件：运行时确认报告元数据合同后，在同宿主多解释器采集应归属同一宿主 build，并保留原始 platform 输出与来源；不同宿主不可被合并。该问题不阻塞非生产研究分支，但发布 OS 矩阵不能只依据旧 JSON 的 release 字段。

## 未观察到失败但仍需保留的风险

- Windows Job 正常和已执行故障路径未观察残留；尚未测试 CloseHandle/TerminateProcess/临时目录删除失败、supervisor 强杀、breakaway、宿主代执行和句柄增长，不保证全部失败路径无泄漏。
- Linux 仅确认已观察的固定后代，故障测试含模拟 launcher；不保证没观察到的后代或崩溃路径。`_run` 的 namespace 后代处理不是通用进程树收集器。
- 默认 Linux suite 会跳过三项真实测试；本轮特意保存默认与 opt-in 两份日志。套件绿灯也包含“反例成功复现”的断言，不能当产品通过。
- FS 拒绝用例将 OSError 视为失败动作，网络用例只验证受控端点有限窗口，不可转写成完整 PolicyDenied/NET-1 结论。
- 没有生产服务、真实管理控制台、外部工具适配、安装器、升级回滚，因此相应 E2E 未执行；本轮不把草案或 mock 补为通过。
