## 风险优先补充矩阵

以下均为未来测试设计，不是本轮已执行项目；优先级 P0 阻塞相应能力发布，P1 阻塞所承诺工作流。

| 类别 | 输入/边界 | 必须观察的结果 / 外部证据 | 优先级 |
|---|---|---|---|
| 初始化与能力 | 缺 helper、不可用 namespace/ACL/网络、未知字段、版本错配、权限不足 | 服务明确失败；用户负载启动计数为 0；不自动改安全设置或降级 | P0 |
| CPU/内存/进程限额 | 单进程和多后代达到边界、低于边界正向、资源释放后再运行 | 整树硬限制符合 capability；拒绝/终止原因区分，宿主不受无界消耗；不以单进程 RLIMIT 冒充整树 | P0 |
| 并发与所有权 | 两会话不同权限、共享工作副本、并发提交/审批/取消、超过限额 | 独立 grant/输出/temp/资源所有权；服务返回明确 Busy 或已约定行为；无越权共享 | P0 |
| 异常输出 | 非 UTF-8、NUL、HTML/ANSI/OSC、伪审批 JSON、大量双流输出、消费者暂停 | 原字节有界保存/封装；UI 不执行控制内容；背压触发合同动作；截断/丢失可见 | P0 |
| 状态与日志一致 | 响应丢失、事件重排/重复/缺号、普通非零退出、审计磁盘满 | 单一终态；查询与事件一致；不凭 stderr 推断拒绝；所要求审计失败时停止新执行 | P0 |
| 重启与残留 | kill 服务、删除权限变化、清理超时、旧 grant/execId 重用 | 不盲目重放，结果未知明确；旧授权无效；残留被报告且禁止不安全复用 | P0 |
| 平台差异 | Windows argv/NTSTATUS/大小写/UNC/编码；Linux fork/FD/signals；macOS 别名/Mach/setsid | 各自原生环境验证，记录具体文件系统与架构；WSL 不替代任一原生平台 | P0/P1 |
| 安装升级回滚 | 干净安装、权限拒绝、中断、配置迁移、N/N-1 版本组合、卸载 | 最小宿主变更可核对并恢复；用户工作区不删除；无法读取新 schema 的旧版本拒绝启动 | P0 |

## 环境安装到清理的联合端到端设计

状态：**未执行，真实链路缺失，阻塞于产品实现及契约冻结**。参考设计 §11.4、PUSH-7 draft.1 和 PUSH-8 AC01–AC19；表中方法名是候选合同，不冻结外部 API。不能使用这份表或协议 fixture 的静态校验声称 E2E 通过。

固定前提：每个平台独立安装已签名/可校验的指定版本；创建一次性无秘密样例仓库与外部合成禁读/禁写文件；记录安装前 OS 配置基线和资源清单；固定版本的外部工具在沙箱外运行，服务负责最终授权。记录 UI、工具、服务、helper、后端、协议、策略/schema、工具链的版本，policy hash、session/exec/request ID、时间、完整命令、退出码、期望/实际与证据。

| 步骤 / 控制台映射 | 真实操作或故障 | 通过条件与必须保存的证据 |
|---|---|---|
| E2E-01 安装→doctor / AC01,17 | 干净安装；第二次以权限不足/缺依赖版本启动 | 正常能力、版本可查；失败条件不启动负载且不擅改主机。安装日志、配置/权限差异、doctor 原始响应 |
| E2E-02 控制台创建环境/会话 / AC02,03,15,16 | UI 保存配置和 session；并发写旧 revision；伪造客户端 role/能力 | UI 引用真实服务状态，版本冲突可见；服务独立拒绝伪造、未知字段和不可表达策略。请求、存储读回、审计、零负载计数 |
| E2E-03 外部工具提交 / AC04,08 | 固定 Agent/harness 在外部提交 file.read→patch→exec(test)；另经两种工具读同一禁文件 | 合法产物 diff 与测试成功；所有禁读均由服务/OS 边界拒绝。真实客户端路由、worker、策略 hash、合成文件结果；不以客户端本地校验替代服务授权 |
| E2E-04 查看结果与日志 / AC06,07,18 | 两流输出、非 UTF-8/伪审批/超限、事件重复/乱序、暂停消费 | 字节保真且有界，终态只一次，查询与事件一致；UI 不执行输出；授权计数不增；脱敏/审计权限可独立检查 |
| E2E-05 拒绝与窄授权 / AC08–11 | 权限拒绝；可信 UI 批准一次；宿主显式新 requestKey；并发消费、重放、过期 | 批准本身不执行；最多一次有效消费；其它请求仍拒绝；grant 不进入模型/worker/日志。服务审计及真实边界访问记录 |
| E2E-06 取消/超时 / AC12 | 带多层后代的长任务、重复取消、与完成竞争、服务计时超时 | ACK 不作已终止；按宽限/强制/回收顺序达到稳定终态；实际 PID+创建时间确认消失；保留已发生副作用，状态不宣称回滚 |
| E2E-07 双客户端断连 / AC13 | 分别断开 Agent owner、控制台 observer、审批 UI；服务断开 ACK | owner 断开按合同取消撤销；observer 断开不误取消；审批过期不默认允许；客户端显示未知，审计能追踪真实结果；禁止自动重放 |
| E2E-08 session.close→清理 / AC14,19 | 正常 close，再注入文件删除失败/残留进程；服务崩溃后重启 | 进程/temp/代理/句柄/授权分别有真实回收检查；不全清理则 closed_incomplete；旧授权不可复用；工作区不被误删 |
| E2E-09 升级→回滚 / AC17,19 | N→N+1 升级、迁移中断、回退 N、卸载保留配置选项 | 安装签名/版本一致，旧配置可恢复；不认识新 schema 时禁写/拒绝；不迁移 grant/进程句柄；ACL/账户/防火墙回到约定基线，工作区内容保留 |

正向闭环和对应负向用例必须在同一被测版本与能力配置下运行。首轮所选平台各执行一次完整闭环，再覆盖关键故障；次数、并发数、资源上限和时间预算由冻结合同确定并记录，不能凭未定默认值判通过。Windows 原生正式路径与免安装路径分别验收；macOS Intel/ARM、Linux 发行版/安全模块/文件系统、WSL 均独立列状态。没有相应 runner 或能力则保持未执行/未验证。

M1 门槛：所支持平台的 §10.2 必需项及 E2E-01–08 全部通过，无静默降级；安装和升级能力一旦交付即执行 E2E-09。M2 门槛：Windows 原生、代理/依赖安装、PTY/后台任务、Node/Python 客户端分别补全矩阵并实际运行；保留已有 M1 回归。任何必需项失败、无能力证据或清理不明均阻塞发布。D4/D5 改变阶段范围时调整排期，不降低验收条件。
