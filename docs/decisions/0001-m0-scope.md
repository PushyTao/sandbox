# 0001：本轮只推进部分 M0 可行性验证

日期：2026-10-14。状态：本轮工程范围已限定；产品决策 D1–D7 仍待确认。

依据：[设计 v0.2](../design/2026-09-30-agent-sandbox-design.md)第 12、14 节明确允许先开展 M0 隔离 PoC，但关键语义未定前不冻结外部 API。本记录不修改原设计，也不把设计中的推荐方案转成已批准决定。

本轮设计副本与原文件的 SHA-256 一致：`5ADE7CF27EAE163360E2635AEFD76A9C3651311B7F41B8443AAE3E5AD75BFDCD`。

## 本轮决定

使用 Python 标准库编写固定、可重复、使用合成数据的 Windows/Linux 探针，产出结构化观察和验收缺口。选择 Python 是降低一次性实验成本，不代表已否决或批准 Rust 生产核心。M0 的报告接口也不是未来 `sbx` 公共协议。

探针不接受任意负载，不配置持久 ACL、账户、防火墙或宿主安全设置。Windows 仅观察 Job 生命周期；Linux 仅观察特定 bubblewrap 参数下的固定行为。macOS 尚无运行证据。`production_ready` 永远为 `false`，本轮产物不满足完整 M0，更不满足 M1 或项目整体目标。

## 进入生产实现前必须解决的契约缺口

1. **Git 写授权与保护优先级。** §4.3 的 `protected` 优先于可写授权，§5.3/D10 又要求可单独审批 Git 元数据写入。需定义硬保护与可审批软保护，或受控的新策略版本变更；仅增加 `writable_roots` 不能覆盖保护规则。未解决前不提供 Git 写 grant。
2. **可信审批通道。** §6.4/§11.2 定义了可信角色，尚需确定身份如何绑定宿主、如何建立控制通道及保护授权凭证。不能依赖模型可控的 `initialize.role`，也不能解析负载 stdout 为审批消息。
3. **直接工作区可表达性。** 只读 bind 或单次 realpath/扫描不能覆盖 hardlink 别名、父目录替换、未来保护文件和启动竞态。需证明挂载/对象约束或选择受控副本；不能以兼容性为由忽略规则。
4. **版本化 runtime profile。** `host-toolchain-v1` 还需具体路径、允许执行的程序、环境生成规则及版本矩阵。PoC 为执行固定程序暴露的只读系统路径不构成生产 scoped read。
5. **审计失败与资源底线。** 需确定完整审计模式和普通诊断模式的默认值、配置和失败处理；明确哪些整树 CPU/内存/进程限制是必需能力。单进程 RLIMIT 不能无条件替代进程树配额。
6. **Linux 嵌套 namespace。** 已有上游实现专门约束负载创建 user/mount namespace，防止绕过路径挂载约束；必须把对应负向案例纳入本项目评估，不能仅测试正常只读写入失败。[固定上游记录](../validation/upstream-references.md)

不可信代码不能自批权限、grant 不能越过硬策略、约束须在负载执行前生效、未知安全字段必须报错，这些仍是不可取消的设计底线。

## 退出条件与后续顺序

M0 结束需要真实三平台 PoC、明确支持策略与拒绝场景、上游复用和自研适配的实测比较、安装恢复约束及 D1–D7 决策记录。目前上述条件尚未全部满足。[验收矩阵](../validation/acceptance-matrix.md)保留每个缺口。

随后实现 M1 的完整离线闭环：严格策略解析与编译、真实网络拒绝、同策略文件 worker、最小环境、会话/RPC、带外授权、输出/取消/清理和审计，并通过设计 §10.2 适用项与 §11.4 样例。M2 再分别验收 Windows 后端、联网代理、客户端、PTY 和后台任务；M3 实现明确服务的凭据 Broker。

本轮范围选择的代价是暂时没有可供 Agent 运行不可信命令的产品。它避免把未经验证的原语或便捷 PoC 提前变成安全承诺；后续仍须完成完整实现和验收。
